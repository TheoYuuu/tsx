# 公开仓库规范

本仓库发布可构建的 TSX 源码、有效测试、必要资源及维护文档。开源不要求公开每轮设计、私人协作或本机运行材料；保留的内容应帮助使用、构建、审查或维护软件。

## 私有开发与公开协作

本项目采用独立的私有开发仓库和公开源码仓库。公开历史从经过审查的源码快照开始，此后正常保留公开变更记录；日常开发只维护一套应用代码。两个仓库使用不同工作区和独立 Git 对象库，不能通过 fork、mirror push、合并私人分支或复制 `.git` 同步。

- 私人计划、协作记录和设计探索放在私有仓库的 `Private/` 范围或仓库外归档。私有仓库也禁止提交密码、私钥、登录状态和真实用户数据。
- 公开同步只读取明确指定的已提交源码快照，按本仓库的范围规则生成文件差异；不带入私人提交消息、作者元数据或历史。先预览并审阅差异，再应用、检查、提交；工具本身不推送。
- 公开 README、AGENTS、Docs 和防护策略由公开仓库维护，不自动被私人文档覆盖。产品源码的公开修复应回流主开发源，避免下一次同步覆盖；防护规则修改需要单独审核。
- 社区贡献通过本仓库的 Issue 和 Pull Request 接收。保留贡献者署名与许可；需要回流私有开发时明确记录对应关系，之后只发布新的实际文件差异，不重复公开私人提交。
- 每次公开前审核完整暂存区以及所有待推送分支/标签可达的历史。公开成功后核对远端内容，保留私有的开发提交与公开提交对应记录。

发布标签必须指向与安装包相对应的应用源码和构建输入。初始源码整理快照可以与既有发行的构建输入相同，但不得声称旧安装包由新的提交重新构建；不因仓库迁移重新签名或修改软件版本。

## 内容准入

| 内容 | 处理方式 |
| --- | --- |
| 应用和运行组件源码、项目配置、锁定依赖清单 | 保留，确保能复现构建且许可完整 |
| 测试、构造夹具、构建/验证/发布工具 | 保留通用且仍有效的内容；不得夹带真实身份或运行产物 |
| 最终图标、必要品牌资源、第三方许可与来源 | 保留实际使用及可重建所需的最小集合 |
| 使用、隐私、架构、构建、发布和验证摘要 | 面向公开读者编写，删除私人路径、账号、对话及内部授权时间线 |
| 设计探索、备选图标、审稿网页、截图集、提示词和过程记录 | 放在仓库外的私有归档，不随公开源码上传 |
| App/DMG、编译缓存、模型权重、下载的依赖目录 | 不入 Git；正式安装包仅按发布流程进入 Release 附件 |
| 密钥、令牌、密码、私钥、证书容器、登录状态、个人配置、私人正文和截图 | 禁止入库、公开日志、Issue、PR 或附件 |

防护规则只接受明确的文件/目录范围；PNG 限于最终应用资源等指定位置，单文件上限为 2 MiB。新目录和二进制文件应先说明公开用途，再纳入审核规则。`.gitignore` 只影响未跟踪文件，不会删除已提交内容，也不能代替暂存区和历史检查。

可公开的目录、文档和文件类型由 `Tools/Repository/policy.json` 明确列出。PNG 还必须匹配 `Tools/Repository/reviewed-images.json` 中的精确路径与 SHA-256；新增或替换图片先查看像素和元数据，再更新清单并审核策略差异，不能仅为消除报错而自动添加摘要。

## 哪些签名信息可以公开

Bundle ID、Team ID、证书公钥/指纹、Sparkle 更新公钥和发布文件的校验值可以用于识别及验签；它们不提供签名能力。真正需要保密的是私钥、含私钥的导出容器、Apple 公证凭据和服务令牌。

签名私钥留在安全的本机或专用发布环境，仓库仅引用公开配置。不要为了「隐藏签名」删除应用更新公钥、完整性验证或预期身份检查，也不要把公开身份标识误称为密钥泄露。

已签名安装包的证书包含开发者公开身份；源码历史清理不会隐藏该身份，也不应为此重签现有发行包。

## 提交与推送检查

从仓库根目录准备固定版本的扫描工具：

```sh
python3 Tools/Repository/bootstrap_gitleaks.py
```

工具从官方来源取得固定 Gitleaks 版本并校验 SHA-256，缓存位于忽略目录。然后运行：

```sh
Scripts/check-public-repo.sh staged
Scripts/check-public-repo.sh tree HEAD
Scripts/check-public-repo.sh history main
```

- `staged` 检查整个 Git 暂存区，即下一次提交的实际内容，而不只检查变更片段。
- `tree [ref]` 检查指定提交的完整文件树，省略 ref 时使用 HEAD。
- `history [refs...]` 检查指定 refs 可达的历史内容和提交元数据；对计划推送的分支/Tag 一并执行。
- `pre-push` 是 hook 的输入接口，按 Git 提供的推送引用检查完整可达历史，防止旧分支重新带回已经移除的材料。

本地 hooks 由维护者明确安装：

```sh
git config core.hooksPath .githooks
```

`.githooks/pre-commit` 检查完整暂存区，`.githooks/pre-push` 检查待推送引用。新提交的作者与提交者使用 GitHub 提供的 noreply 邮箱；历史扫描也核对作者、提交者和 Tagger 元数据。CI 提供另一层检查；不能认为本地 hook 自动安装到每位贡献者环境，或把 CI 当作首次发现秘密的合适时机，因为代码在 CI 启动前已经上传。

修改 `.gitignore`、扫描配置、hooks、仓库检查工具或 CI 等防护策略时，先审阅实际暂存差异，再执行 `Scripts/check-public-repo.sh policy-review` 取得该差异的 SHA-256。提交时通过 `TSX_REVIEWED_POLICY_SHA256` 提供已审核的摘要；差异变化后须重新核对。此机制只防止疏忽，不是用户审批或独立安全边界，也不会跳过内容扫描。

遇到告警先复核路径、类型和来源，输出应脱敏。真实秘密不得用联网请求「试一下是否有效」。误报需要有具体证据和最小范围例外，不能整体关闭规则、忽略整类凭据或绕过 hook。

## 双仓库文件同步

在独立公开工作区使用已提交的导出工具，先生成预览。将示例路径和源码引用替换为实际私有工作区与已确认提交；预览包含私有提交标识，只保存到仓库外的私有记录。

```sh
python3 Tools/Repository/export_public.py --source ../private-development --ref main
```

工具使用公开仓库当前已提交的范围规则，读取私有提交中的文件内容，不读取其未提交修改或缓存，不导入提交历史。预览列出新增、修改、删除和跳过路径；私有目录明确排除，未知路径会停止。README、AGENTS、公开文档和防护策略由公开仓库维护，跳过项需要单独审查，不能以为已自动同步。

确认每项差异后，使用预览中的 `plan_sha256` 应用同一方案：

```sh
python3 Tools/Repository/export_public.py --source ../private-development --ref main \
  --apply --expect-plan REVIEWED_PLAN_SHA256
```

目标工作区必须干净且与私有源使用独立历史。`Tools/Repository/export-state.json` 只记录已管理公开文件的摘要与模式，不记录私有提交；首次在两边内容相同时建立基线。公开文件独立改变后，先将贡献回流或明确解决差异，工具不会直接覆盖。删除只针对已纳管文件。工具仅修改文件，不暂存、提交、推送或发布；之后仍须逐项暂存、完整检查并执行相应验证。

防护工具及同步状态变化也属于策略审核范围。初次创建公开仓库时，先从已审查快照独立初始化，再在隔离候选中建立同步基线并审阅最终初始内容；不能通过克隆私有仓库来初始化公开历史。

## 人工内容审核

自动扫描不能理解所有私人内容。提交前还应检查：

1. 新增或修改的文本是否包含私人对话、授权过程、真实账号、个人路径、联系方式、翻译正文或内部运行记录。
2. 每张新增或修改图片的实际像素和元数据；检查桌面、浏览器、菜单栏、设备码、账户与凭据展示。模糊或黑条不应保留可还原的源文件/图层。
3. 测试数据是否专门构造，日志是否仅含必要固定状态，构建产物、依赖和大型文件是否误入暂存区。
4. 公开资源是否有必要且具备许可；删除设计过程材料时不得误删最终应用资源、构建输入或必要第三方声明。

审计报告只记录范围、方法、脱敏定位、结果和限制，私有备份位置不写进公开文档。扫描通过不等于不存在所有敏感信息。

## 历史处理与限制

普通删除或添加 `.gitignore` 不能清除旧提交。已发布秘密应先撤销或轮换，再按授权范围清理分支、Tag 和历史，并检查公开附件及引用。改写历史前做仓库外私有备份，核对远端状态并安排协作者同步；不要把旧历史 merge 或 push 回清理后的仓库。

历史清理不能收回他人已下载的 clone、fork、缓存、补丁或附件，也不能保证托管平台立刻删除按旧提交地址仍可访问的对象。需要时联系托管平台处理残留；任何说明都应保留这些边界。历史作者信息是否调整属于单独的隐私和协作决定，不通过修改当前文件假装已清除。
